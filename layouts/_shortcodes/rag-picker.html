Text-to-SQL RAG

Your data is already structured. Instead of embedding rows into vectors, convert the user's question into a SQL query and run it directly against your database. Libraries like LangChain's SQLDatabaseChain or vanna.ai can help. No embedding model or vector database needed.

This is not RAG in the traditional sense, but it solves the same problem: answering natural-language questions over your own data.

Recommendation

Graph RAG

Your questions need to follow relationships between entities — drug interactions, case precedents, supply chains. Build a knowledge graph (e.g. Neo4j) and retrieve by graph traversal instead of, or alongside, vector similarity.

Graph construction from unstructured text is expensive and error-prone. Start with a small, well-defined entity set and expand gradually. Consider adding a self-correction layer if the domain is high-stakes.

Recommendation

Agentic RAG

Your questions span multiple data sources, so no single retrieval method covers everything. Use an LLM agent that can choose which tool to call — vector search for documents, SQL for tables, graph traversal for relationships, web search for recent information.

Add guardrails: maximum iterations, timeouts, and a fallback to simpler retrieval. Agents can loop or pick the wrong tool, so test thoroughly with real queries.
